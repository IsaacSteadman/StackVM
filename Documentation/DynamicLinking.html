Dynamic Linking & Kernel Linker Features (Workstream C3)

This page documents the linker capabilities the StackVM toolchain provides for building a Linux-style kernel and a dynamically-linked userspace: the static-linker features (--gc-sections, --build-id, --emit-relocs, --whole-archive, symbol-version scripts, and ELF linker scripts) and the dynamic-linking ABI (PLT/GOT model, dynamic relocations, the DT_* contract, and the -shared/-pie output format). The ELF interchange format itself is described alongside the object/executable APIs; this page builds on the EM_STACKVM machine (0x5356) and the base relocation types R_STACKVM_64 / R_STACKVM_PC64 / R_STACKVM_RELATIVE defined there.

Static linker features

--gc-sections

Garbage-collects input sections that are not reachable from a set of roots by following relocation edges (a relocation in a live section to a symbol defined in section S keeps S live). The roots are:

  • the section that defines the entry symbol (-e/--entry, default _start);
  • sections that define any symbol named by -u/ --undefined;
  • KEEP sections — .init_array and .fini_array are always kept (the linker synthesises their boundary symbols), plus any pattern named by a KEEP(...) directive in the linker script;
  • every exported global when producing a shared object / PIE (-shared/-pie); and
  • all sections of legacy single-segment objects and all .debug* sections (never collectable).

As with GNU ld, collection is at section granularity: to drop individual unused functions/data the compiler must emit one section per function/datum (the equivalent of -ffunction-sections / -fdata-sections). The list of collected sections is reported in LinkResult.removed_sections and summarised on the link command line.

--build-id[=style]

Emits a .note.gnu.build-id note (NT_GNU_BUILD_ID = 3, owner "GNU") into the linked ELF. Styles: sha1 (default, 20 bytes), md5 (16 bytes), uuid (16 random bytes), 0x<hex> (an explicit id), or none (disabled). The sha1/ md5 ids are computed over the final image (and its relative relocation offsets) so identical inputs reproduce identical ids. Inspect with readelf -n.

--emit-relocs

Retains the symbolic relocations applied during the link as .rela.text / .rela.data sections in the output ELF (each entry references a .symtab symbol with type R_STACKVM_64 or R_STACKVM_PC64 and the original addend). This is the input a KASLR-style post-processor or a self-relocating kernel uses to re-fix the image at an arbitrary load base; it complements the R_STACKVM_RELATIVE base-relocation stream (the .rela.dyn already produced for absolute data references).

--whole-archive / --no-whole-archive

Positional toggles: archives listed while --whole-archive is in effect contribute every member to the link (as if the members had been listed individually), rather than only the members that resolve an outstanding undefined symbol. --no-whole-archive restores the default on-demand extraction. This is how kbuild links built-in.a.

Symbol-version scripts (--version-script)

A constrained GNU version-script grammar is supported: 

VERS_1.0 {
  global: api_*; init_module;
  local:  *;
};
VERS_1.1 { global: new_api; } VERS_1.0;

Named and anonymous nodes, global:/local: blocks with plain names or glob patterns, and } PARENT; dependencies parse. A symbol matched by a local: pattern and not by any global: pattern is localized (its binding becomes LOCAL and it is removed from the exported global / dynamic symbol table). The associated version name is available via version_for() for future versioned-symbol emission. Localized symbols are reported in LinkResult.localized_symbols.

ELF linker scripts (vmlinux.lds)

In addition to the output-section ordering, the script parser recognises ENTRY(symbol) (used as the default --gc-sections entry root) and KEEP(*(pattern)) directives (whose patterns become GC roots).

Dynamic-linking ABI

A shared object or PIE is an ET_DYN ELF. The dynamic metadata lives in a dedicated read/write PT_LOAD segment placed after the data segment, with a PT_DYNAMIC program header pointing at .dynamic. The object publishes its global symbols through .dynsym/.dynstr with a SysV .hash table, and carries its load-base relocations in .rela.dyn.

.dynsym records both directions of the link contract: the defined exports this object provides (with their owning section and value) and the undefined imports it references but does not define. Imports are emitted as STB_GLOBAL / SHN_UNDEF entries with a zero value and are listed in the .hash table so the loader can bind them against the global symbol search order at run time. Because a shared object / PIE defers those references to the loader, undefined symbols are not link-time errors when -shared/-pie is in effect (matching ld's default). Each DT_NEEDED names a library that is expected to satisfy them. Inspect the dynamic symbol table with readelf --dyn-syms (or readelf -s, which prints both .symtab and .dynsym).

PLT / GOT model

Position-independent code reaches external data and functions indirectly through a Global Offset Table (.got) and Procedure Linkage Table (.plt):

  • Each imported data object gets a .got slot fixed up by an R_STACKVM_GLOB_DAT dynamic relocation; PIC reads the address from the slot rather than embedding it.
  • Each imported function gets a .plt stub whose .got.plt slot is fixed up by an R_STACKVM_JUMP_SLOT relocation. Eager binding resolves all slots at load; lazy binding leaves the slot pointing at the loader's resolver trampoline (reachable via DT_PLTGOT) which resolves on first call.
  • The R_STACKVM_RELATIVE stream rebases all internal absolute pointers in one pass — this is the only relocation the kernel's early self-relocator needs.

Loader contract (informative)

  1. Map each PT_LOAD segment at vaddr + load_base with the segment's R/W/X permissions.
  2. Process R_STACKVM_RELATIVE entries first (rebase) so the dynamic tables become usable.
  3. For each DT_NEEDED, recursively load the named object.
  4. Resolve R_STACKVM_GLOB_DAT / R_STACKVM_JUMP_SLOT (and any R_STACKVM_COPY) against the global symbol search order, eagerly or lazily via DT_PLTGOT.
  5. Run DT_INIT / DT_INIT_ARRAY in dependency order, then transfer control to the executable entry point.

Status. The toolchain emits and inspects the full static feature set and the ET_DYN container with .dynsym/.dynstr/.hash/ .dynamic/.rela.dyn and the DT_* contract above. .dynsym carries both the defined exports and the SHN_UNDEF imports, the seven R_STACKVM_* relocation types (including GLOB_DAT/JUMP_SLOT/COPY) are defined and recognised by the inspector, and everything is verified with readelf -d/-n/-r/--dyn-syms. The compiler -fPIC GOT/PLT code generation (which is what actually emits GLOB_DAT/JUMP_SLOT relocations and the .plt/.got tables) and the runtime dynamic loader in the emulator are intentionally deferred to the dynamic-userspace milestone (E2 step 5); this document is the ABI they target.
