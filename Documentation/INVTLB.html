INVTLB (TLB Invalidation Group)

INVTLB is opcode 0x0F. The byte immediately following the opcode selects the sub-operation. INVTLB instructions are privileged and may only be executed at kernel privilege level (priv_lvl = 0).

Note: This opcode replaces the old INT (0x0F) opcode. Software interrupts are now issued via CALL_E with the IS_INT flag.

Sub-Operations

Sub-Op Code Name Description Stack Effect
0x00 INVTLB_BEGIN Begin a TLB shootdown sequence. Pops the target TLB pointer (tlptr), the virtual address base (vaddr_base), and the region size (vaddr_size) from the stack. The implementation may send an IPI to all other cores to invalidate the specified range. [UInt64 tlptr, UInt64 vaddr_base, UInt64 vaddr_size] -> []
0x01 INVTLB_COMMIT Commit the TLB invalidation initiated by INVTLB_BEGIN. Clears the pending invalidation state. Must be called after INVTLB_BEGIN. [] -> []

Encoding

An INVTLB instruction is always 2 bytes: [0x0F][sub_op]. Sub-op values 0x02 and above are reserved.

Privilege

Both sub-operations require kernel privilege (priv_lvl = 0). Executing INVTLB at user privilege triggers a PROTECT_FAULT.
