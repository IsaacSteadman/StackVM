C _Complex support

IsaacCompiler implements the C99/C11 _Complex floating types (float _Complex, double _Complex and long double _Complex), the GNU spelling __complex__, and the standard <complex.h> conveniences built on top of them. _Imaginary is accepted as an alias for _Complex.

Value model

A complex value is laid out exactly like struct { T re, im; }: 2 * sizeof(T) bytes with the real part at offset 0 and the imaginary part at offset sizeof(T). So sizeof(float _Complex) is 8, sizeof(double _Complex) is 16, and a complex value aligns like its element type. Whole complex values are always moved component-wise, so every element width stays on the fast load/store path.

Operators

FormMeaning
__real__ z / __imag__ z The real / imaginary component as an assignable lvalue.
a + b, a - b, a * b, a / b Complex arithmetic. A real operand is promoted to complex (real part = the value, imaginary part = 0).
-aNegates both components.
a == b, a != b Component-wise equality, yielding bool.
a = b, a += b … Assignment / compound assignment to a complex lvalue.
__builtin_complex(re, im) Construct a complex value from two real parts.

Conversions follow Annex G: real -> complex sets the imaginary part to zero; complex -> real takes the real part.

Multiplication / division

(a + bi)(c + di) = (ac - bd) + (ad + bc)i
(a + bi)/(c + di) = ((ac + bd) + (bc - ad)i) / (c*c + d*d)

<complex.h>

complex aliases _Complex; I / _Complex_I is the imaginary unit; creal, cimag, conj and the CMPLX family are provided as macros over the operators above.

Mangling

Complex types mangle with the Itanium-ABI C prefix followed by the element-type code: Cf (float), Cd (double), Cg (long double).
